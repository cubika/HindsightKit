# ProvenLoop 0.1.0-alpha.0.12

Date: 2026-09-08. Channel: Windows Design Partner Preview.

This preview adds opt-in learning from ordinary user corrections and an agent's
own captured investigation and recovery. It also processes learning work
incrementally and coordinates database users before an upgrade. M0/MVP remain
No-Go for quality release; `0.1.0-alpha.1` remains an unapproved target.

## Install or upgrade

Close every Copilot Session that loaded 0.11 or an earlier preview before the
first upgrade to 0.12. Those processes do not participate in the new maintenance
protocol. Published 0.11 uses SQLite schema 10; 0.12 upgrades it to schema 14.
Start new Copilot Sessions after installation to load the matching runtime.

```powershell
irm https://raw.githubusercontent.com/cubika/ProvenLoop/v0.1.0-alpha.0.12/install.ps1 | iex
```

The installer verifies the Release tarball's SHA-256 checksum, installs into a
separate user-local runtime slot, and switches PATH after integration succeeds.
Keep the prior slot and the verified pre-upgrade snapshot. An older runtime
cannot read schema 14; switching PATH alone cannot roll back this migration.
See [installation and operations](../alpha-installation.md) for recovery steps.
This preview uses GitHub Release tarballs and is not published to the public
npm registry.

## Enable automatic learning

Installation enables collection and, on a fresh bootstrap install, retrieval
and correction-learning capabilities. Background model requests require a
separate opt-in. Existing capability settings and consent survive upgrade.

With capture and the worker enabled, run:

```powershell
provenloop enable retrieval
provenloop enable correction_learning
provenloop learning enable --confirm
provenloop learning approve-hooks --cwd C:\path\to\repository --confirm
provenloop learning status
```

Read the disclosure before accepting it. The learner sends bounded, redacted
conversation and tool excerpts to GitHub Copilot using the existing sign-in.
These excerpts can include user corrections, agent summaries and captured tool
results. Isolated background requests have no tools or plugins; Copilot usage
and retention policies apply.

Automatic retrieval hooks are verified only for Copilot CLI `1.0.84-1` and
require approval for each exact repository root. Restart that Copilot Session
after approval. Other compatible host versions can retain capture and explicit
MCP access, but automatic hook behavior is unverified. Use
`provenloop learning disable` to stop inference or `provenloop learning mute`
to mute notices.

## What can become knowledge

- Ordinary corrections can produce repository-scoped proposals about code,
  data meaning, documents or plans, without fixed correction fields. Exact
  source quotations remain mandatory.
- Agent research needs a captured summary and the captured tool results it
  cites. Findings remain unverified candidates. A URL or summary alone cannot
  establish project applicability.
- Supported MCP invocation recovery and repository test-command substitutions
  can activate narrow rules when native failure, changed retry and successful
  completion establish the required proof. Agent recovery also needs a later
  summary and cannot bridge an intervening user correction.

Broad semantic claims and research findings remain candidates outside ordinary
Context. Explicit Knowledge controls remain user-owned. Automatic activation
does not certify semantic correctness or productivity benefit. Scope, version
or revision, conflicting evidence, deletion and revocation still control reuse.
Agent statements never
become user confirmation or permission grants.

Learning uses a durable incremental queue, bounded 32-event windows, a daily
request budget and resumable jobs. Source enrichment can revisit evidence
without another model request. Revisions and retries retain their original
expiry and attempt budget. Long investigations and cross-task retrospective
learning remain outside this slice.

## Upgrade coordination

For Sessions already running the participating runtime, upgrade pauses new
ProvenLoop MCP and background database work, then waits up to 15 seconds for
current work to drain. A drain timeout removes the pause before migration or
Extension shutdown, so those Sessions can continue. Context reports temporary
maintenance; Explain and Feedback return a retryable maintenance error.

After draining, upgrade stops ProvenLoop Extensions and retains the database
leases through snapshot, migration, plugin replacement and rollback. Inference
cleanup with unknown ownership stops the upgrade before migration. Copilot
itself remains open, but successful upgrade still requires a Session restart
to load the new plugin/runtime. There is no hot reload of old MCP processes.

## Validation limits

The [general correction experiment](../general-learning-validation.md) ran 40
authored windows through the real isolated provider. It produced 33 semantic
proposals, all retained as candidates with no automatic activation. A separate
eight-window bilingual typed experiment remained incomplete after two output
validation failures; later successful retries do not replace those failures.

The [agent experience experiment](../agent-experience-validation.md) ran 12
authored windows. Two research findings remained candidates; two supported
recoveries received narrow receipts in runtime replay. One premature-summary
output was rejected, so the evaluator reports `complete: false`.

These experiments used synthetic captured excerpts and had no independent
human labels. They do not establish precision, recall, live installed-host
adoption or controlled benefit. The broader catalog includes unexercised
cases. Retained Windows capture, provider-degradation, remote-upgrade and
field-effect evidence remain separate quality-release requirements.
