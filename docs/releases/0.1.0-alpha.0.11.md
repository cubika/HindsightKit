# ProvenLoop 0.1.0-alpha.0.11

**Date:** 2026-09-07
**Channel:** Windows Design Partner Preview

This compatibility update carries forward the
[0.10 capability scope](0.1.0-alpha.0.10.md). It does not change schema 10,
runtime deadlines, or the quality-release boundary: **M0/MVP remain No-Go**,
and `0.1.0-alpha.1` remains an unapproved quality-release target.

## Install or upgrade

```powershell
irm https://raw.githubusercontent.com/cubika/ProvenLoop/v0.1.0-alpha.0.11/install.ps1 | iex
```

Use this new versioned URL even if an older installer rejected your Node.js
version. Previous tags and their installers remain unchanged.

The installer verifies the Release tarball's SHA-256 checksum and installs it
into a separate user-local runtime slot. It switches PATH only after validation
and integration succeed. This preview is not published to the public npm registry.
See [installation and operations](../alpha-installation.md) for opt-outs and
rollback.

## Runtime compatibility

- Node.js `>=22.16.0` and npm `>=11` no longer have artificial upper bounds.
  The installer, package engines, and Doctor use the same minimum-only policy;
  Node.js 24.14.0 is no longer rejected merely for being a newer major version.
- Required SQLite backup and busy-timeout support are still checked. Newer
  version numbers do not override missing runtime capabilities.
- The Node.js 22 Winget default and pinned development tools remain reproducible
  defaults, not runtime ceilings. CI covers Node.js 24 alongside the baseline.
- Copilot CLI remains `>=1.0.71`, with its existing command-capability checks.
  Plugin/runtime identity and persisted-format compatibility checks stay strict.

## Quieter SQLite startup

Only SQLite's experimental-feature notice is suppressed during module loading,
including the CLI, Extension runtime, background search reader, and installer
probe. Normal warning handling is restored immediately afterward; unrelated
warnings and real SQLite errors remain visible.

This also prevents Windows PowerShell 5.1 from treating that notice as a native
command exception and interrupting the installer.

## Release boundary

Upgrade from 0.10 uses the existing schema and versioned-slot mechanism. Keep
the previous runtime and recovery snapshots when upgrading older installations.
This release adds compatibility and warning-handling regressions, not native-host
field acceptance, lossless capture guarantees, or proof of controlled benefit.
