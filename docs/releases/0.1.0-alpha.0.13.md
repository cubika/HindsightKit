# ProvenLoop 0.1.0-alpha.0.13

Date: 2026-09-08. Channel: Windows Design Partner Preview.

This preview repairs Windows upgrade recovery, including plugin-directory
uninstall failures with `os error 32` and `os error 5`. It retains 0.12's opt-in
automatic learning from ordinary corrections and captured agent investigation.
M0/MVP remain No-Go for quality release; `0.1.0-alpha.1` is still an unapproved
target. This is not evidence of controlled benefit.

## Install or upgrade

Use the version-pinned bootstrap for the GitHub Release tarball/checksum channel:

```powershell
irm https://raw.githubusercontent.com/cubika/ProvenLoop/v0.1.0-alpha.0.13/install.ps1 | iex
```

The bootstrap verifies the exact Release tarball, stages a versioned user-local
runtime and switches PATH after successful integration. npm installs that local
tarball; this preview is not published to the public npm registry.

You do not need to close every foreground Copilot session just to upgrade.
ProvenLoop drains participating runtimes and retires only ownership-verified
remaining helpers. Old tools may disconnect: open a new session or use a
host-supported reload to load the updated integration. Hot reconnection is not
guaranteed, and capture pauses while its Extension is stopped.

Keep the prior runtime slot and recovery snapshots. Both 0.12 and 0.13 use SQLite
schema 14; published 0.11 used schema 10. Older databases require explicit upgrade,
and switching PATH to an old runtime does not roll back a migrated database.
See [installation and operations](../alpha-installation.md) and
[plugin process recovery](../plugin-process-recovery.md).

## What changed

### Graceful shutdown before legacy cleanup

- Participating MCP servers register their shutdown lifecycle, finish accepted
  requests and exit the protocol loop. Lifecycle failures remain explicit.
- Upgrade drains learning, worker, observation, projection and MCP database
  leases, requests graceful shutdown, and awaits registered participants before
  targeting remaining legacy helpers. The drain timeout removes the maintenance
  barrier before migration or participant shutdown.
- Legacy cleanup recognizes exact ProvenLoop MCP runtime slots and launchers,
  including numeric version components, and separately attested extension
  bootstrap PIDs. It verifies Windows owner, parent, path and creation identity.
- Legacy extension attestation uses bounded parent startup logs. Foreground
  Copilot, current ancestors and unrelated processes are excluded. Unknown
  ownership never grants termination; no broad name-based or process-tree kill
  is used.
- Native failures include bounded phase/reason and Windows error diagnostics,
  without exposing private command lines or full process inventories.

### Guarded locked-directory recovery

If directory uninstall still returns Windows errors 5 or 32, recovery can refresh
only the strict known plugin layout in place from verified bundled package assets.
It backs up files and affected configuration, checks registration ownership and
concurrent changes, and preserves unrelated settings. It does not delete or rename
the held directory.

The verified package version and immutable marketplace tag identify the replacement.
Recovery does not invent Copilot `source_sha` values; local asset integrity is
recorded separately. Failed writes or later verification trigger guarded rollback.
External edits are preserved for review, and rollback failures are explicit.

### Verified retry without changing user choices

Only after verified plugin registration and SQLite `quick_check` may recovery
clear the exact recognized generic stale schema-recovery `lastError`.
Enabled/disabled capabilities and automatic-learning consent remain unchanged.
Unsupported future capabilities remain unavailable. Unrelated errors, canonical-data-changed review
warnings and recovery snapshots are retained. Outer failure handling no longer
overwrites the specific canonical-data-changed warning with a generic recovery error.

The bootstrap checks the target runtime's existing state even if inherited PATH
still selects an older runtime. A matching installed plugin version takes the
verification path instead of unnecessary uninstall/reinstall, entering maintenance
recovery only when the exact recognized stale schema-recovery diagnostics remain.
Repeated installation and version-match verification respect `-NoAutoCollect`.

## Automatic learning still requires consent

Fresh bootstrap installation enables in-scope capabilities unless opted out;
upgrades preserve existing settings. Capability switches are not consent to
background model requests. With capture and the worker enabled, review the
disclosure before opting in:

```powershell
provenloop enable retrieval
provenloop enable correction_learning
provenloop learning enable --confirm
provenloop learning approve-hooks --cwd C:\path\to\repository --confirm
provenloop learning status
```

Learning sends bounded, redacted excerpts to GitHub Copilot using the existing
sign-in. Background requests have no tools or plugins; Copilot usage and retention
policies apply. Automatic retrieval hooks require separate approval for each exact
repository root and are verified for Copilot CLI `1.0.84-1`. Restart the affected
session after hook approval. Use `provenloop learning disable` to stop extraction.

Ordinary corrections and captured agent findings can produce source-backed
candidates. Only supported, fully verified recovery predicates qualify narrow
active rules; research and broad semantic findings remain candidates outside
ordinary Context. Agent text never counts as user confirmation.

The [0.12 release notes](0.1.0-alpha.0.12.md),
[general correction validation](../general-learning-validation.md) and
[agent experience validation](../agent-experience-validation.md) describe the
inherited features and earlier experiments. Their incomplete experiments and
coverage limits still apply; they are not new 0.13 evidence.

with a native Windows directory handle fixture that denies delete sharing.

are not a real user's 0.13 upgrade or an observation of hot reconnection.
