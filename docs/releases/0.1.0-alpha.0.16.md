# ProvenLoop 0.1.0-alpha.0.16

Date: 2026-09-11. Channel: Windows Design Partner Preview.

This preview classifies saved engineering experience and retrieves it across
different task descriptions. It adds concept-assisted search, a deeper search
tool, optional source pointers, and reviewed background enrichment. It also
includes the learning, lifecycle, and scalability fixes developed after 0.15.

## Install or upgrade

```powershell
irm https://raw.githubusercontent.com/cubika/ProvenLoop/v0.1.0-alpha.0.16/install.ps1 | iex
provenloop learning status
provenloop ui
```

The installer verifies the exact GitHub Release tarball and SHA-256 sidecar.
This preview uses GitHub Releases without publishing to the public npm registry.
Restart Copilot or reload the integration after upgrade to expose the new tools.

Canonical storage advances from schema 16 in 0.15 to schema 23. Use the normal
maintenance upgrade path and retain the previous runtime and a compatible
snapshot. Ordinary viewer and runtime opens do not silently migrate old data.
Older readers cannot open schema 23. Explicit collection and learning opt-outs
remain effective.

## Experience discovery

Experience gains optional purpose, topic, and entity classifications with
recorded applicability and exclusions. Lexical and concept routes share a
bounded candidate pool and canonical source checks. Ranking prioritizes task
relevance, distinguishes unresolved conditions, and preserves exact identifiers
and case-sensitive commands. A topic match does not grant scope or evidence.

`provenloop_context` retains its maximum of three items and 1,200 estimated
tokens. `provenloop_search` supports deeper queries, alternate descriptions,
entity hints, purpose/topic filters, and deliberate rediscovery of previously
seen experience. It defaults to eight results, with a maximum of 12 and 3,000
estimated tokens. Explain rechecks the current scope, sources, revision, and
controls before showing a search result.

File, directory, and URL references are optional navigation. They are not fetched
automatically and do not establish verification. Manual `remember` and reviewed
`knowledge replace` accept `--purpose`, `--topics`, `--source`, and `--source-kind`.
`knowledge show` and `knowledge list` expose the discovery profile. Metadata
corrections preserve superseded history and remain subject to the current
review digest.

Confirmed irrelevant feedback changes ranking only for the matching task and
profile revision, with a 30-day limit. It does not archive a valid lesson. Search
usage remains separate from automatic context and user-reported adoption.

## Learning and background data use

New reusable lessons receive a separate model quality review. Lesson prose uses
English while quotations retain their original language; reviewed search aliases
support original-language queries. Long investigations select useful evidence
within bounded requests. Deterministic input-size failures no longer repeatedly
consume model attempts.

When background learning is enabled, idle passes can classify saved lesson text
and conditions through the existing Copilot sign-in and service quota. Extraction
and independent review each count against the same daily request budget. Requests
have tools disabled, and the existing Copilot service policies apply.
`provenloop learning disable` also stops this enrichment.

Enrichment jobs are durable, resumable, and bounded. Publication checks the
current lesson, source digests, vocabulary version, and user overrides. Accepted
metadata is stored separately and cannot strengthen evidence, broaden scope, or
renew expiry. Deleted or revoked sources cannot restore an old profile.

Reviewed policy replacement and independent-evidence renewal preserve their
existing controls. Temporary instructions remain task-local. Source-supported
references retain their evidence labels; model review is not external verification.

## Reliability and compatibility

This release reduces unnecessary history grouping, source-reading, and index
update work. Retrieval refills after filtering and suppresses duplicate guidance,
while every backend page remains bounded. Source and control changes between
pages are rechecked before delivery. Windows observation archives retry transient
atomic replacement failures without deleting the destination first.

These repairs improve specific tested paths. They do not establish sustained
capacity for an indefinitely growing history. Missing trusted repository identity
continues to produce a diagnostic rather than guessed scope.

## Validation and remaining limits

The tag-triggered release workflow runs lint, type checking, unit and integration
tests, packed-artifact installation/upgrade checks, and a Windows PowerShell 5.1
installer dry run before creating the release assets. Development validation
also exercised schema migration, source deletion, Forget/reset, background
enrichment cancellation, quota accounting, and current-source publication checks.

A 25-query synthetic development corpus found relevant experience for all 19
answerable queries, compared with 13 for a lexical-discovery ablation. Candidate
recall was 100% versus 57.1%; returned-item precision was 100% in both runs.
The corpus informed implementation fixes and is not held-out acceptance evidence.
It does not measure real incident retrieval, model classification quality, or
developer productivity. The default path uses no vector model or foreground
model reranker.

M0/MVP remain No-Go for a quality release. `0.1.0-alpha.1` is an unapproved target.
Real-corpus relevance, installed-host model behavior, sustained capacity, and
controlled benefit remain open validation work. See the
[experience retrieval design](../experience-retrieval-design.md),
[installation guide](../alpha-installation.md), and
[scalability review](../scalability-review.md).
